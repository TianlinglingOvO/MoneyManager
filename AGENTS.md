# Repository Guidelines

## Project Structure & Module Organization

- `src/` contains the React/Vite PWA. `InsightsPage.tsx` owns `/`; `/analytics` redirects there. `BillsPage.tsx` owns the flat recent, monthly, and yearly bill views. `CategoriesPage.tsx` owns category management at `/categories` (sidebar under 资金, phone header icon); `SettingsPage.tsx` keeps appearance, budget, status, backup, and connection info.
- Reuse shared components in `src/components/`; keep Recharts imports inside lazy-loaded `FinanceCharts.tsx`. `AccountPicker.tsx` owns in-app account search (every picker for an existing account uses it instead of a native select); `FundsMissingAccountDetails.tsx` owns aggregated missing-account review. `src/form-state.ts#useDirtyCheck` gives every editable sheet its dirty flag.
- Keep category composition filtering, percentage calculation, and adaptive sector spacing in `src/category-composition.ts`; do not duplicate those rules in page components. Keep same-progress comparison labels in `src/insights-comparison.ts`.
- `src/appearance.tsx`, `src/device-background.ts`, and `src/ledger-clock.tsx` own appearance, local backgrounds, and ledger date. Tokens and responsive layouts live in `src/styles.css`.
- `server/` contains app services; `server/funds.ts` owns accounts, movements, transfers, adjustments, refunds, reconciliation, activation baseline, and funds exports. `server/matters.ts` owns borrowers, loans, repayments, subscriptions, payments, plans, ledger links, and matter exports. `server/budgets.ts` owns budget aggregates and `server/health.ts` owns deterministic ledger checks. `shared/` holds Zod schemas/types; `db/` holds migrations (current version 12); `tests/` holds coverage.
- `shared/app-metadata.ts` exposes the external SMB brand and reads the canonical version from `package.json`. Editable brand SVGs and generated PWA icons live in `public/`; regenerate PNGs with `scripts/build-brand-assets.ps1`.
- Treat `data/`, `backups/`, `.env`, `output/`, `dist/`, and `dist-server/` as generated or private.

## Build, Test, and Development Commands

Use Node.js 22+; prefer `npm.cmd` on Windows:

- `npm.cmd run dev`: start API and Vite.
- `npm.cmd test`: run Vitest once.
- `npm.cmd run typecheck`: validate browser and server TypeScript.
- `npm.cmd run build`: create production output; `npm.cmd start` serves it.
- `npm.cmd run backup:snapshot -- <label>`: create and integrity-check a pre-deployment SQLite snapshot.
- `npm.cmd run backup:verify-restore -- [snapshot]`: restore a snapshot in a disposable directory, boot an isolated service, compare counts, and recheck SQLite.

## Coding Style & Naming Conventions

Use strict TypeScript, two-space indentation, semicolons, and double quotes. Use `PascalCase` for components/types and `camelCase` for functions/variables. Prefer `@/` and `@shared/` imports. Validate with Zod and store currency in integer minor units. Extend semantic CSS tokens; preserve 44px mobile targets, visible focus, WCAG AA, and `prefers-reduced-motion`.

## Architecture & Safety Invariants

- SQLite is authoritative. Browser storage may contain appearance, device layout, scroll/filter state, and device-only images, but never ledger copies or amount/note drafts.
- `localDate` is the occurrence date; `createdAt` is recording time. Period boundaries, “today,” and relative dates must use `LedgerClock` from `/api/v1/settings`, not the browser timezone.
- Matters are statistically separate from the ledger. Only an explicit `LedgerLink` may create or reference a transaction; that transaction and the matter never synchronize afterward. CNY loan links must match amount and kind, while USD subscription links represent the actual CNY charge.
- Funds tracking is opt-in. Never backfill or require accounts for records before `funds.started_on`; post-activation effective income/expense records that are not baseline require an active CNY account, or a USD/USDT account plus the actual foreign `accountAmount`.
- Activation snapshots every existing transaction into `funds_baseline_transactions`. Baseline records stay without accounts, stay out of account movements, and must not appear as missing-account findings. Never assign an account to a baseline record without explicit user confirmation. Health still uses `localDate >= startedOn`, but only together with the baseline exclusion.
- Accounts may be `CNY`, `USD`, or `USDT`. Default income and expense accounts must stay CNY. Ledger `amount` is always CNY; a foreign account must store the real foreign debit/credit separately and must never guess an exchange rate.
- Missing-account health is one aggregated issue per month with related IDs, not one card per transaction. Batch assignment is CNY-only and must preview net funds impact before submit.
- Account balance is opening balance plus append-only `account_movements`. Never add or mutate a separate balance field. Business edits, account changes, soft delete/restore, refunds, loans, repayments, subscription payments, plan completions that create expenses, transfers, and undo must reconcile movements in the same SQLite transaction.
- The movement list describes each source (category and note, transfer route, borrower) and labels later appends for the same source and account as `change`, `reversal`, or `restore`; it never merges or rewrites movements. Account balances may be zero or negative in every form: activation, account edit, and calibration.
- Transfers and adjustments never affect income, expense, budgets, or charts. A transfer moves credited principal and records only the debit-credit difference as one expense fee. Full refunds preserve the original transaction, exclude it from statistics, and append compensating movements; partial refunds remain unsupported. Refund and undo-refund live in the transaction edit sheet, not on every bill row; a refunded transaction is read-only until the refund is undone, and refunding an untracked (pre-activation or baseline) transaction requires a CNY account.
- Funds-aware loans and repayments change account cash and receivables without creating ordinary income/expense entries. USD subscription payments require the actual CNY charge, an expense category, and a payment account. If that payment account is USD or USDT, also require the actual foreign `accountAmount`.
- Accounts accept normalized exact IDs, names, or aliases for OpenClaw; ambiguous references must fail. An account cannot be archived while nonzero, default, or actively referenced, and only an account with no funds history may be permanently deleted.
- Loan repayments belong to one loan and cannot exceed its outstanding amount. Subscription renewals never advance automatically: only a recorded payment advances the anchored month/year/custom cycle. Inside the reminder window a renewal is “即将续费”; only on or after the billing date is it “待确认” (`confirmCount`). Cancelling acts immediately with undo, and cancelled subscriptions stay listed under 已取消 where they can be reactivated. Keep CNY and USD summaries separate; `monthlyEquivalent` counts yearly plans as 1/12 and custom cycles per 30 days.
- New-loan UI must use the searchable in-app borrower picker. Creating a new borrower and its first loan is one matter transaction; normalized active names are reused and archived names must be restored explicitly.
- Preserve soft-deleted borrowers, loans, repayments, subscriptions, payments, and plans for 30 days. Full JSON and matter CSV exports must not silently stop at the API page limit, and matter screens load every page of borrowers, loans, subscriptions, and plans instead of truncating at the first one.
- Keep matter writes and optional ledger creation in one SQLite savepoint/transaction. OpenClaw matter writes require `direct` mode, a unique `requestId`, version checks, and reversible operation snapshots.
- Budgets are independent per natural month, use integer CNY minor units, never roll over, never block entries, and remain statistically separate from matters. Archived categories may retain unchanged budget values but cannot receive new ones. Merge category budgets on category migration. Only expense categories can be fixed (`categories.is_fixed`, e.g. rent): the month-end forecast counts fixed-category spending as recorded and extrapolates only the rest by elapsed days.
- Ledger health rules must remain deterministic and read-only. Acknowledgements store only rule fingerprints and timestamps. Budget warnings fingerprint month, scope (total/forecast/category), and near/over band — never spent or forecast amounts — so acknowledging an overspend survives later entries in the same band. Large-expense findings flag a fixed category only at 1.5× its 90-day median; other categories keep the 3× median or 20%-of-budget rule. Health money text uses thousands separators. Health MCP results must not include transaction notes.
- SMB has no built-in AI analysis and makes no external model calls; ledger interpretation is OpenClaw's job through the read-only MCP tools. The legacy `ai_reports` table is kept for existing rows but nothing writes to it.
- Browser transaction writes require `expectedUpdatedAt` and same-origin validation. MCP Service Token requests remain isolated under `/mcp`.
- `/mcp` JSON-RPC parse failures, missing or stale sessions, and GET/DELETE session failures must return JSON-RPC errors. Do not map those client mistakes to the generic HTTP 500 copy `服务暂时无法完成请求`.
- OpenClaw batch entry is all-or-nothing, accepts at most 20 explicit transactions, uses one `requestId`, and produces one reversible operation. Never infer missing amount, date, kind, or category.
- All OpenClaw proposal writes require a unique `requestId` and stable request hash. Same-ID replays return the original proposal; different content conflicts. Operations left `running` for over 15 minutes become `failed` with a sanitized reason.
- Persistent SQLite databases use WAL plus `synchronous=FULL`. Snapshots and pre-migration backups must pass both `integrity_check` and `foreign_key_check`. Status exposes local, remote, and restore-verification timestamps/states, never paths, commands, or credentials.
- Production `npm start` / `打开 SMB.cmd` / `start-production.ps1` must supervise `dist-server` so Settings “检查并刷新” can reload a newer on-disk build without compiling in-process. The reload endpoint is browser same-origin only, not MCP. Unsupervised processes only refresh the PWA. Status may say whether reload is supervised, never how to spawn Node.
- Keep insight period/kind in shareable URL parameters. Preserve drill-down return context and bill scroll/filter state. Finance reports must use the ledger timezone’s today, not `new Date()`. An in-progress week/month/year compares the matching days of the previous period, never the whole previous period; the summary card must name 较上月/上周/去年同期 and show that previous date range, and category detail must show the previous-period amount next to the percentage.
- Keep insight category panels mutually exclusive: detail shows rank, amount, previous-period amount, and same-progress change; composition shows every current positive-value category in the donut and legend with amount, share, and drill-down. Never collapse categories into an `other` slice.
- Keep bill navigation flat and URL-compatible: `/bills` is recent, `view=ledger&period=month` is monthly, `view=ledger&period=year` is yearly, and `view=trash` is the global period-independent trash. Never persist trash mode in session state or inherit it during insight drill-down. Bill search matches the note, the category name, or an exact amount, and can widen from the period to all time; the period card's “导出当前视图” (`/api/v1/transactions.csv`) follows the current filters, while full exports stay in Settings.
- A normal transaction delete is always soft. Permanent transaction deletion is allowed only from trash with `updatedAt` conflict protection. Category purge requires a fresh impact revision plus exact-name confirmation, removes all category transactions atomically, detaches matter links, rejects affected pending proposals, and invalidates related undo snapshots. It is deliberately non-undoable; do not add a bulk “empty trash” action.
- Shared sheets/dialogs are centered with at least 32px viewport clearance above 900px and become full-width bottom sheets at 900px or below. Keep their header and footer fixed, scroll only the body, hide the drag handle on desktop, and preserve Android safe-area/back behavior.
- Shared sheets/dialogs must manage and restore focus, support Escape/Android back, use content-specific close labels, and confirm before discarding dirty forms. Background polling must not replay entry animations.
- Every MCP tool must carry annotations from `toolAnnotations(name)` in `server/mcp.ts`; keep the `get_`/`list_` = read-only naming contract when adding tools.
- The SMB → OpenClaw daily reminder (`server/openclaw-reminder.ts`) is off unless its hook URL, token, channel, and recipient are configured. It runs on the ledger clock, reads only subscription/plan attention counts, calls the hook only when something is pending (one `smb-reminder-<date>` idempotency key per day, at most 6 attempts), sends counts but never names, amounts, or notes, and never exposes the hook URL or token in status or logs.
- Never use `window.confirm`/`alert`/`prompt`. Reversible soft deletes act immediately and offer `offerUndo` (toast with 撤销); funds-affecting or irreversible actions use `ConfirmSheet`, `DangerConfirmDialog`, or an in-sheet confirm; every editable `BottomSheet` form passes `dirty` for the in-sheet discard prompt. Enabling OpenClaw direct mode and undoing an OpenClaw operation each ask first.
- Health-check drill-down actions must close the current sheet before opening another sheet or navigating. Root budget warnings open the matching `BudgetSheet`; category budgets, transactions, subscriptions, plans, and foreign-key findings use explicit destinations.
- Matters badges count subscription attention plus plan attention. Mirror those counts on the matching tabs. Default new Matters visits to subscriptions while subscription attention exists, otherwise to plans while plan attention exists, otherwise loans. Never force-switch a user already viewing a Matters tab.
- Plans are one-shot financial follow-ups. Creating a plan stores title plus optional due date and CNY amount, and never binds an account. Completing a plan without an amount only changes status. Completing with an amount must create or link an expense in the same SQLite savepoint; after funds activation that write requires an active CNY account, or a USD/USDT account plus the actual foreign `accountAmount`. After the link, the plan and transaction never synchronize. Cancelled or linked plans cannot be reopened by PATCH.
- Appearance offers `warm-paper`, `ink-night`, and `auto`. `auto` resolves on the client from `prefers-color-scheme` (rechecked on focus and visibility) and in `public/theme-boot.js`; the schema folds the retired `porcelain`/`sage-ledger` into `warm-paper` before validation so the accent and background survive. There is no density setting; a legacy `density` in a patch is accepted and never stored.
- Settings shows the ledger timezone read-only. Keep `PATCH /api/v1/settings/timezone` for first-run initialization and `direct_update_timezone` for OpenClaw.
- Insights keeps period, grain, and kind in one sticky `.insights-bar` whose period label is the page `<h1>`. DOM order is overview → charts → recent: at ≥1280px grid areas put charts left and overview plus recent right; narrower screens keep the overview right below the summary. Budget and health rows appear only for a month of expenses. The summary card also shows the other kind and the balance. The trend card switches between daily and cumulative (`trend=cumulative` in the URL; cumulative draws the previous period's same-progress total dashed). On phones the pinned bar condenses to one row after scrolling.
- Open plans show dated and undated columns together (side by side on desktop, stacked on phones); there is no scope switch.
- Page backgrounds, including personal images, render on the fixed `body::before` layer; do not reintroduce `background-attachment: fixed`, and keep `isolation: isolate` on `body`, or body's own background colour paints over the layer.
- Keep the budget category adder as a themed in-app picker with keyboard focus return; do not regress it to an OS-native select whose popup ignores Ink Night tokens.
- Keep motion centralized in `src/motion.ts`: micro feedback is 120–160ms, panels/routes are 220–280ms, trend charts are 800ms, and donut charts are 900ms. Start chart motion only after matching non-placeholder data arrives, play it once on session entry or deliberate user changes, and disable both CSS and Recharts animation for `prefers-reduced-motion`. Recharts completion must use its lifecycle callbacks; never stop chart animation with a wall-clock timer.
- Personal image bytes stay in IndexedDB. OpenClaw cannot modify appearance. Never log credentials, notes, amounts, or sensitive request bodies. Unhandled request errors may log only method, path, and error name.
- The in-app boot splash is decorative, pointer-free, session-once, shorter than 800ms, and skipped for `prefers-reduced-motion`; it must never delay data initialization or replay on routing/background refresh.
- Keep `/api`, `/auth`, `/cdn-cgi`, and `/mcp` outside PWA navigation caching.
- Boolean query parameters are true only for `true` or `1`; never parse query strings with `z.coerce.boolean()`, which turns "false" into true.
- The external product is `SMB — Sutady Moneybook`, positioned as `私人账本`. The mark always uses `#291D3A`, `#F06B55`, and `#FFF3E4`; themes must not recolor it. Keep domain, database paths, environment variables, Cloudflare configuration, MCP name `sutady-money-manager`, cache keys, and export format unchanged.
- `package.json` is the only version source. Increment patch for fixes/polish, minor for backward-compatible features, and major for product identity or incompatible contracts. Health, status, settings, and MCP metadata must import the shared version instead of hard-coding it.

## Testing & Change Review

Name tests `*.test.ts` or `*.test.tsx`; use Supertest and React Testing Library. Cover precision, authorization, timezone boundaries, funds activation-day existing/new/baseline distinctions, foreign-account dual amounts, plan complete-with-ledger vs status-only, MCP JSON-RPC error mapping, URL state, sorting, focus behavior, undo conflicts, and mobile layouts. For visible changes, inspect 1440×900, 1024×768, and 412×915; assert dialog bounding boxes, edge clearance, handle visibility, fixed actions, and 44px mobile targets instead of relying only on semantic snapshots. Capture stable Playwright completion-state screenshots only after chart `data-animation-running` becomes `false`; keep comparison artifacts under `output/playwright/`. Then run tests, typecheck, and build.

Use imperative commits such as `Refine insights navigation`. PRs should describe behavior/data changes, verification, migration/configuration impact, and screenshots. Maintain local Git history on `main`; never configure or push a remote without explicit authorization. Back up production SQLite before deployment; never commit databases, backups, tokens, keys, or `.env`.
