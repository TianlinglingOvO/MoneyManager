# 资金追踪使用与维护指南

“资金”是 SMB 2.3.0 起提供的可选人民币账户模块。它回答“钱现在在哪个账户、实际还有多少”，但不改变原有收入、支出、预算和事项的统计口径。

## 启用前先理解

- 资金追踪必须由账本所有者在“资金”页面主动启用；升级程序不会自动启用。
- 启用向导中的余额应填写确认启用当下的真实可用余额，而不是根据旧账倒推的余额。
- `总资金 = 所有有效账户的初始余额 + 全部追加式资金流水`。系统没有第二个可直接修改的余额字段。
- 启用前的旧账继续参与账单和图表，但不会追溯到账户，也不会生成资金流水。
- 启用后的普通收支需要账户；网页默认使用对应的默认账户，OpenClaw 未明确指定时也由服务端使用默认账户。

启用后应先核对账户名称、真实余额、默认收入账户、默认支出账户和手续费分类。只有确认这些值准确后再保存。

## 各类操作如何影响资金

| 操作 | 账户余额 | 收支、图表和预算 |
| --- | --- | --- |
| 普通支出/收入 | 对应账户减少/增加 | 正常计入 |
| 借出/还款 | 支付账户减少/收款账户增加 | 不作为普通支出/收入 |
| 订阅付款 | 支付账户减少 | 作为普通支出计入 |
| 账户间转账 | 转出减少、转入增加 | 本金不计收支 |
| 转账手续费 | 从转出账户额外扣除 | 只计一次支出 |
| 余额校准 | 追加一笔差额流水 | 不计收支 |
| 全额退款 | 追加反向流水 | 原账保留并从统计中排除 |

资金流水采用追加和补偿方式。修改账目、换账户、软删除、恢复、退款和撤销时，服务会在同一 SQLite 事务中重新计算应有影响并追加差额，不直接篡改历史流水。

## “启用资金追踪后的账目缺少账户”

这条体检提示表示：账目仍在收入/支出统计中，但没有 `accountId`，因此无法可靠对应某个账户余额。当前体检按账目逐笔生成提示，所以多笔账目会出现多张同名卡片。

处理前先判断账目的真实时间关系：

1. **确实在启用资金追踪后新增的账目**：打开账目并选择实际发生资金变化的账户。
2. **启用前已经存在，且其金额已经包含在启用时填写的真实余额中**：不要补账户，否则可能重复影响余额；暂时使用“标记已核对”。

### 2.3.0 已知边界

当前 `funds.started_on` 只保存账本日期，体检条件是 `localDate >= startedOn`。因此，启用当天早些时候已经存在的无账户账目也可能被误判为启用后的账目。开发修复应保存明确的启用基线或创建时间边界，并把同类结果聚合展示；不能仅靠发生日期推断，也不能批量给历史账目补账户。

## 账户管理规则

- 账户只支持 CNY，可以为负数，但负余额会进入账本体检。
- 有非零余额、仍是默认账户或仍被有效业务引用的账户不能停用。
- 只有从未产生资金流水且没有关系的账户才能永久删除。
- OpenClaw 可用账户 ID、精确名称或标准化别名；存在歧义时必须拒绝并询问用户。
- 转账的转出和转入账户不能相同。实际扣款大于到账金额时，差额必须作为手续费支出处理。
- 第一版只支持全额退款。退款后的原账保留，不能重复退款；退款撤销仍受后续修改冲突保护。

## OpenClaw、导出与恢复

OpenClaw 的资金写入只允许在 `direct` 模式执行，必须携带唯一 `requestId`；修改类操作还需要最新版本。可逆操作进入 30 天操作记录，账户歧义、手续费分类缺失或退款条件不明确时必须先询问用户。

- 完整 JSON 包含账户、别名、资金流水、转账、校准和退款状态。
- `/api/v1/funds/movements.csv` 导出账户流水。
- `/api/v1/transfers.csv` 导出转账。
- SQLite 快照自然包含全部资金数据；恢复演练会核对资金表，并在临时服务中验证一次写入、读回和清理后的余额一致性。

## 开发接手位置

- `server/funds.ts`：账户、流水、转账、校准、退款和资金对账的唯一领域服务。
- `server/health.ts`：资金缺失、负余额、孤立流水和不平衡规则。
- `src/pages/FundsPage.tsx`：启用向导、账户和流水页面。
- `db/migrations.ts`（版本 9）：资金表和现有业务字段迁移；不要手工改正式数据库表。
- `tests/funds.test.ts`、`tests/funds-ui.test.tsx`：资金引擎与界面回归。

新增资金行为时，必须同时覆盖业务记录、资金流水、软删除/恢复、退款或撤销、幂等重放、导出和恢复验证。任何路径都不得绕过 `FundsService` 直接修改余额。
