# 资金追踪使用与维护指南

“资金”是 SMB 2.3.0 起提供的可选账户模块，2.4.1 起支持人民币、美元和 USDT 账户，以及启用瞬间的历史基线。它回答“钱现在在哪个账户、实际还有多少”，但不改变原有收入、支出、预算和事项的统计口径。账本金额始终按人民币记账；外币账户另存实际扣款或到账金额。

## 启用前先理解

- 资金追踪必须由账本所有者在“资金”页面主动启用；升级程序不会自动启用。
- 启用向导中的余额应填写确认启用当下的真实可用余额，而不是根据旧账倒推的余额。
- 每个币种各自计算：`该币种资金 = 该币种有效账户的初始余额 + 该币种追加式资金流水`。系统没有第二个可直接修改的余额字段，也不把人民币和外币加总成一个数字。
- 启用前的旧账继续参与账单和图表，但不会追溯到账户，也不会生成资金流水。启用瞬间会把当时已有账目标记为历史基线。
- 启用后新增的普通收支需要账户；网页默认使用对应的默认人民币账户，OpenClaw 未明确指定时也由服务端使用默认账户。选择美元或 USDT 账户时必须另填实际外币金额，不得查询或猜测汇率。默认收入/支出账户必须是人民币账户。

启用后应先核对账户名称、真实余额、默认收入账户、默认支出账户和手续费分类。只有确认这些值准确后再保存。

## 各类操作如何影响资金

| 操作 | 账户余额 | 收支、图表和预算 |
| --- | --- | --- |
| 普通支出/收入 | 对应账户减少/增加；外币账户按实际账户金额变动 | 按人民币账本金额计入 |
| 借出/还款 | 支付账户减少/收款账户增加 | 不作为普通支出/收入 |
| 订阅付款 | 支付账户减少 | 作为普通支出计入 |
| 有金额的计划完成 | 支付账户减少 | 作为普通支出计入 |
| 账户间转账 | 转出减少、转入增加 | 本金不计收支 |
| 转账手续费 | 从转出账户额外扣除 | 只计一次支出 |
| 余额校准 | 追加一笔差额流水 | 不计收支 |
| 全额退款 | 追加反向流水 | 原账保留并从统计中排除 |

资金流水采用追加和补偿方式。修改账目、换账户、软删除、恢复、退款、有金额的计划完成和撤销时，服务会在同一 SQLite 事务中重新计算应有影响并追加差额，不直接篡改历史流水。计划录入本身不扣账户；只有完成入账才会减少支付账户。

资金页「最近资金流水」默认按发生日倒序（同日再按录入时间），在固定高度窗口内滚动并分页加载，校准记录不进入该列表。`GET /api/v1/funds/movements` 可用 `sort=recent|oldest`，默认 `recent`。完整 JSON 与 CSV 导出仍按创建时间排列，便于存档对账。

## “启用资金追踪后的账目缺少账户”

这条体检提示表示：账目仍在收入/支出统计中，但没有 `accountId`，因此无法可靠对应某个账户余额。2.4.1 起同月多笔缺少账户会聚合成一条提示，可在体检详情中展开核对，并批量指定人民币账户；提交前会显示对所选账户余额的净影响。

处理前先判断账目的真实时间关系：

1. **确实在启用资金追踪后新增的账目**：打开账目或使用聚合提示中的批量指定，选择实际发生资金变化的账户。
2. **启用瞬间已经存在的基线旧账**（`fundsBaseline`）：不要补账户，否则可能重复影响余额。这类记录不会出现在缺少账户提示里。

启用仍保存账本日期 `funds.started_on`，同时把启用当下已有账目写入 `funds_baseline_transactions`。体检条件是发生日期不早于启用日、且不是基线记录。不要只按 `localDate >= startedOn` 给历史账目补账户。批量补录只允许人民币账户。

## 账户管理规则

- 账户币种可以是 CNY、USD 或 USDT。账户余额可以为负数，负余额会进入账本体检。人民币与外币汇总必须分开，不能合成一个总额。
- 有非零余额、仍是默认账户或仍被有效业务引用的账户不能停用。
- 只有从未产生资金流水且没有关系的账户才能永久删除。
- OpenClaw 可用账户 ID、精确名称或标准化别名；存在歧义时必须拒绝并询问用户。
- 转账的转出和转入账户不能相同。实际扣款大于到账金额时，差额必须作为手续费支出处理。
- 第一版只支持全额退款。退款后的原账保留，不能重复退款；退款撤销仍受后续修改冲突保护。

## OpenClaw、导出与恢复

OpenClaw 的资金写入只允许在 `direct` 模式执行，必须携带唯一 `requestId`；修改类操作还需要最新版本。可逆操作进入 30 天操作记录，账户歧义、手续费分类缺失、外币金额缺失或退款条件不明确时必须先询问用户。不得猜测汇率。

- 完整 JSON 包含账户、别名、资金流水、转账、校准和退款状态。
- `/api/v1/funds/movements.csv` 导出账户流水。
- `/api/v1/transfers.csv` 导出转账。
- SQLite 快照自然包含全部资金数据；恢复演练会核对资金表，并在临时服务中验证一次写入、读回和清理后的余额一致性。

## 开发接手位置

- `server/funds.ts`：账户、流水、转账、校准、退款、启用基线和资金对账的唯一领域服务。
- `server/health.ts`：资金缺失、负余额、孤立流水和不平衡规则；缺少账户按月聚合。
- `src/pages/FundsPage.tsx`：启用向导、账户和流水页面。
- `src/components/AccountPicker.tsx`、`src/components/FundsMissingAccountDetails.tsx`：账户选择与缺少账户核对。
- `db/migrations.ts`（当前版本 11）：资金表、币种、实际账户金额、启用基线和一次性计划；不要手工改正式数据库表。
- `tests/funds.test.ts`、`tests/funds-ui.test.tsx`：资金引擎与界面回归，须覆盖启用当天旧账/新账和外币双金额。

新增资金行为时，必须同时覆盖业务记录、资金流水、软删除/恢复、退款或撤销、幂等重放、导出和恢复验证。任何路径都不得绕过 `FundsService` 直接修改余额。
